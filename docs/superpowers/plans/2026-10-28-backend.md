**Goal:** Deliver a runnable HTTP backend that recommends synthetic student activities, with optional Gemma ranking and a reliable offline fallback.

**Architecture:** Local JSON feeds a deterministic candidate selector. A server-side Gemma adapter optionally ranks eligible candidates; the HTTP service exposes students, activities and recommendations to the frontend.

**Tech stack:** Reuse any runtime already introduced by the team. If none exists, use Node.js JavaScript with its built-in HTTP server, fetch and test runner; keep the backend independently runnable in `backend/` with no required third-party dependencies.

**Spec:** PROJECT.md and the interface contract below. These interfaces are the starting contract for Agy; document any necessary changes before changing them.

## HTTP contract for the frontend

Default local port: `3001`; allow `PORT` override. JSON responses use UTF-8. Support the configured frontend origin through `FRONTEND_ORIGIN` and preflight OPTIONS requests.

`GET /api/health` -> HTTP 200, `{"status":"ok"}`. This reports service health, not verified Gemma connectivity.

`GET /api/students` -> `{"students":[{"id":"student-1","name":"Alex","interests":["running"]}]}`.

`GET /api/activities` -> `{"activities":[{"id":"activity-1","name":"Social Run","description":"A relaxed campus run","tags":["running"],"start":"2026-11-01T10:00:00Z","end":"2026-11-01T11:00:00Z","location":"Campus","source":"synthetic"}]}`.

`GET /api/students/student-1/recommendations?limit=5` ->

```json
{
  "studentId": "student-1",
  "recommendations": [
    {"activityId": "activity-1", "reason": "Matches your interest in running."}
  ],
  "mode": "fallback",
  "notice": "Using interest-based recommendations."
}
```

`mode` is `gemma` or `fallback`; `notice` is a user-safe string or null. The frontend resolves activity details using `/api/activities`. Empty eligible results return HTTP 200 with an empty recommendations array. Default limit 5; accept integer limits 1 through 20. Invalid limits return 400; unknown students and routes return 404. Errors have shape `{"error":{"code":"STUDENT_NOT_FOUND","message":"Student not found."}}`; use `INVALID_LIMIT`, `NOT_FOUND` and `INTERNAL_ERROR` for the other cases. Never return credentials, raw provider responses or stack traces.

## Task 2: Deterministic recommendations

Files: `backend/src/recommendations.js`, `backend/src/server.js`, `backend/test/recommendations.test.js`, `backend/test/http.test.js`.

- [ ] Expose a selector accepting student, activities, attendance, limit and an injected current time. Exclude activities whose start is at or before now and activities already attended by this student.
- [ ] Normalize tags and interests by trimming and lowercasing. Score each activity by twice its unique interest-tag overlap plus its unique overlap with tags from this student's past attended activities. Retain only positive scores; sort by descending score, ascending start time, then ID. Apply the requested limit.
- [ ] Generate truthful deterministic explanations from matching interests or past attendance. Return empty results when no relevant eligible activities exist.
- [ ] Add the recommendations endpoint and limit validation using the contract above.
- [ ] Use fixed-time fixtures to test past and already-attended exclusions, interest matches, attendance-only matches, ties, duplicate tags, no matches, limits and unknown students. Verify two calls with identical inputs give identical output. Run `npm test`; commit.

## Task 3: Optional Gemma adapter

- [ ] Implement one documented provider interface using `GEMMA_BASE_URL`, `GEMMA_MODEL` and optional `GEMMA_API_KEY`; an OpenAI-compatible chat-completions endpoint is acceptable only if the selected host supports it. Verify the host's actual request format before claiming live integration works.
- [ ] With no provider configured, run immediately in fallback mode. With configuration, send only the synthetic student's interests, relevant attendance tags and at most 20 eligible candidates. Ask for JSON containing activityId/reason pairs ranked by relevance. Use a bounded timeout of 5 seconds.
- [ ] Require a nonempty valid list with unique IDs drawn only from the supplied candidate set and nonempty reason strings of at most 500 characters. Reject the entire provider result on invalid JSON, unknown or duplicate IDs, or malformed entries. Slice valid results to the requested limit. Skip the provider for empty candidate sets.
- [ ] On timeout, network failure, non-success response or invalid output, return deterministic results with `mode: fallback` and a safe notice. Never expose the raw provider error to the frontend.
- [ ] Mock provider calls in tests: valid ranking, hallucinated IDs, duplicates, blank reasons, invalid JSON, timeout and provider failure. Tests must run without credentials or external network access. Run `npm test`; commit.
